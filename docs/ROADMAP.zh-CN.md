# 路线图

[English](ROADMAP.md) | [简体中文](ROADMAP.zh-CN.md)

本文说明 Tencent Cloud AIGate 的演进方向。这是一份"活"的高层计划：只定方向——具体怎么
实现，在各自启动时再决定。日常执行以 issue 为准，已交付内容记录在
[CHANGELOG.md](../CHANGELOG.md)。

## 近期已交付（v0.1.x）

当前的能力基座：双协议数据面（OpenAI + Anthropic）、分层 token 配额与用量记账、
凭据保险柜与 BYOK、签名 Webhook 事件、幂等导入与自助密钥。明细见 changelog。

## 当前 — v0.2

下一个版本的三个方向，围绕"让模型调用更稳、网关更易于扩展"：

- **模型降级** —— 主模型无法服务时自动降级到备用模型：上游的偶发故障不再直接打断请求。
- **自动路由** —— 不再固定按绑定顺序，而是按可配置策略在可用模型中选择：把成本、时延、能力偏好写成配置。
- **插件支持** —— 插件能力服务于自动路由：路由策略以插件形式提供，自定义策略可以直接接入、不改网关内核。

## 下一步 — 候选

- **更细的配额管理** —— 按用户、按分组更灵活的配额配置。
- **可观测性** —— 请求、错误与时延指标，为看板与告警做好准备。

## 更远 — 探索中

- **质量感知路由** —— 不止看成本与时延，也参考实测质量来选择模型。
- **多实例协同** —— 多副本部署时保持配额与路由状态一致。

## 暂不涉及（现阶段）

- Web 界面 —— AIGate 按设计是纯 API 服务。
- MCP 代理与会话管理 —— 属于相邻层。

## 我们如何做规划

- 日常执行以 issue 为准；本文随版本规划修订。
- v0.x 范围内，API 与配置保持向后兼容；如有例外会在 changelog 中明确标注。
- 欢迎通过项目的 issue 渠道提出反馈与设计讨论。
