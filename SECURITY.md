# Security Policy

## Supported versions

Security fixes are applied to the latest v0.1.x release. If you run a fork,
rebase onto the latest release before reporting an issue that may already be
fixed.

## Reporting a vulnerability

Do **not** open a public issue for security problems.

Use GitHub's private vulnerability reporting:

1. Open the repository's **Security** tab.
2. Choose **Report a vulnerability**.
3. Include the affected version, deployment mode (SQLite/MySQL, container or
   binary), reproduction steps, and the impact you believe is possible.

Please redact API keys, upstream credentials, customer data and internal
hostnames from logs and screenshots.

We will acknowledge the report, investigate, and coordinate a fix and disclosure
timeline with you. Good-faith research that follows this policy is welcome.
